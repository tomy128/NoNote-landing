# NoNote 官网落地页设计

> Date: 2026-07-27  
> Status: Confirmed  
> Repository: `NoNote-landing`

## 用户目标

NoNote 官网服务个人知识工作者、开发者、研究者和重度文件使用者。页面需要帮助首次访客依次完成四件事：

1. 在十秒内理解 NoNote 是什么。
2. 判断它是否能解决已有本地资料难以检索和再利用的问题。
3. 通过真实界面、Local-First 边界和开源信息建立信任。
4. 下载适合当前操作系统的安装包，或前往 GitHub 进一步了解。

首屏核心表达：

```text
NoNote
Not Only Notes.
Everything you keep, finally useful.
```

中文不逐字翻译，建议表达为：

```text
NoNote
不只是笔记。
让你保存的一切，真正为你所用。
```

辅助说明明确产品类别：

> 一个 Local-First 的 AI 工作空间，让本地文件、笔记和资料可以被搜索、理解、对话和继续创作。

## 核心 tradeoff

官网选择“安静可信的产品展示”为主体，局部加入未来感和可探索交互。它不会采用重型 3D、长视频、概念化 AI 动画或大规模运行时依赖。

这一选择牺牲部分视觉奇观，换取：

- 更快的价值理解；
- 更强的产品可信度；
- 更低的首屏性能成本；
- 更好的移动端和无障碍体验；
- 更低的长期维护成本。

页面保留足够趣味性，但每个交互都必须解释产品或改善下载体验。

## MVP 范围

### 包含

- 中英文独立页面和语言切换；
- 根据浏览器语言选择初始语言；
- Hero 产品主张、说明、下载 CTA、GitHub CTA 和真实产品界面；
- 产品工作流解释；
- 四项核心能力；
- Local-First 和隐私边界；
- 真实产品使用场景；
- macOS Apple Silicon、macOS Intel 和 Windows x64 下载入口；
- FAQ、最终 CTA 和完整页脚；
- SEO、社交分享、无障碍、响应式与性能优化；
- 轻量产品演示、工作流切换、Local-First SVG 轨迹和下载反馈。

### 不包含

- 博客、文档站和定价系统；
- 登录、账户、支付或邮件订阅；
- 用户评价、客户 Logo、下载量等尚无真实来源的社会证明；
- 视频制作；
- 复杂 3D、WebGL 或依赖大型动画库的效果；
- CMS、多页面应用框架或运行时国际化框架；
- 默认启用的统计、Cookie 和第三方追踪。

## 信息架构

### 1. Header

包含 Logo、Product、Privacy、Download、GitHub 和语言切换。桌面端为紧凑顶部导航；移动端使用可访问的展开菜单。下载始终是视觉主操作。

### 2. Hero

首屏用一句强主张建立品牌记忆，用一句具体说明解释产品类别。主 CTA 根据操作系统显示推荐下载，次 CTA 指向 GitHub。

真实产品主截图承担主要视觉证明。截图可以使用轻量热点展示“搜索资料、打开引用、得到答案”的一次闭环。首屏必须在交互脚本失败时仍显示完整静态截图和有效链接。

### 3. 工作方式

用四步解释产品：

```text
Keep → Understand → Ask → Create
保存 → 理解 → 提问 → 创作
```

用户点击步骤时切换对应界面和说明。移动端使用纵向步骤，避免横向内容溢出。

### 4. 核心能力

只展示与当前产品闭环直接相关的能力：

- 统一理解 Markdown、TXT、PDF 和 DOCX；
- 关键词与语义结合的混合搜索；
- 基于真实文件引用的 AI 对话；
- 将有价值的 AI 结果保存为可编辑笔记。

避免使用四张完全相同的功能卡。能力应围绕真实界面和使用故事排布。

### 5. Local-First 信任区

用简洁 SVG 路径说明：

- 原文件留在用户的文件系统；
- NoNote 在本地建立元数据和索引；
- 用户自行选择云端或本地 AI Provider；
- 写入、移动和删除等副作用必须经过明确边界和确认。

滚动时可以逐步点亮路径，但静态状态必须已经可读。这里同时链接 GitHub 或隐私说明。

### 6. 产品实景

通过两到三个真实场景串联产品界面：

1. 导入研究资料并生成摘要和标签；
2. 搜索跨文件信息并查看引用；
3. 与资料对话并将结果保存为 Note。

截图需要来自实施时最新的已发布产品版本，并在素材文件名或清单中记录对应 tag。首版固定采集：

- Hero：包含 Workspace、文档阅读区和 Assistant 的完整工作台；
- Search：一次混合搜索及其真实结果列表；
- Assistant：带文件引用的回答及引用跳转状态；
- Save as Note：回答预览和用户确认保存状态。

允许裁切、隐藏个人路径与敏感内容、添加说明标记和组合画面，不得伪造尚未存在的功能。截图采集前应创建无敏感信息的演示 Workspace，使中英文页面都能获得自然且可读的素材。

### 7. 平台与下载

系统识别仅用于突出推荐项，不隐藏其他平台：

- macOS Apple Silicon DMG；
- macOS Intel DMG；
- Windows x64 NSIS 安装包。

下载 URL 集中在配置文件。识别失败时展示全部平台。每个下载项包含版本、架构、文件类型和系统要求；GitHub Release 作为可恢复入口。

下载信息的权威来源是 `tomy128/NoNote` 最新的已发布 GitHub Release，而不是草稿 Release 或仓库内应用版本号。构建前的同步脚本读取 Release 元数据，只接受现有发布流程定义的三个精确资产模式：

```text
NoNote_<version>_macos_aarch64.dmg
NoNote_<version>_macos_x86_64.dmg
NoNote_<version>_windows_x86_64-setup.exe
```

同步结果写入可审查的 `src/content/releases.json`，正式构建只读取该文件，不在浏览器运行时请求 GitHub API。若 Release 不完整、资产为空或模式不匹配，构建失败。系统最低版本是人工核验字段：Windows 当前只可填写代码已声明且经发布验收的 Windows 10 22H2 或更新版本；macOS 最低版本在发布测试明确前不得猜测，缺失时页面显示“查看 Release requirements”并链接对应 Release。

### 8. FAQ

首版回答：

- 我的文件会被上传吗？
- NoNote 支持哪些文件？
- 是否支持本地模型？
- NoNote 是否免费和开源？
- 支持哪些系统？
- 如何获取更新或报告问题？

FAQ 使用原生 `details` / `summary`，确保无需脚本即可操作。

### 9. Final CTA 与 Footer

末屏重申核心价值并提供下载与 GitHub。Footer 包含仓库、Release、License、隐私说明、语言入口和版本信息，不添加尚未维护的社交账号。

## 视觉系统

### 视觉方向

采用 “Quiet Product Confidence”：

- 延续桌面产品的深绿色品牌识别；
- 使用纯白主背景、清晰墨色文本和少量深色叙事区；
- 通过大字号主张、非对称截图和有节奏的留白建立品牌感；
- 真实界面是页面的视觉中心；
- 避免模板化卡片墙、暖米色背景、AI 紫色渐变和无意义的玻璃效果。

建议以应用现有颜色为输入，将官网 token 转为 OKLCH，并重新验证所有前景与背景组合：

- Brand reference: `#245c46`;
- Ink reference: `#18201c`;
- Canvas reference: pure white;
- Subtle surface reference: `#f5f6f3`;
- Dark narrative surface: 近黑中性色；
- Secondary accent: 与深绿色在色相和明度上均明确区分，只用于少量状态和视觉引导。

最终实现禁止在组件中散落颜色值，统一使用语义化 CSS custom properties。

### 字体

选择支持中英文的现代无衬线系统，品牌语气是“安静、机械、清醒”。字体必须经过真实字库验证，不使用常见 AI 模板字体组合。优先方案：

- 正文采用系统 UI 字体栈，保证加载速度和跨平台清晰度；
- 品牌展示字体仅在确有辨识度收益时自托管；
- 中文与英文字形需要分别检查标题字重、字面大小和断行；
- 正文最小 16px，行长控制在 65–75ch；
- 展示标题最大不超过 96px，字距不小于 `-0.04em`。

### 图形与截图

- 使用项目真实 Logo 和桌面端截图；
- 图标采用同一套 SVG 线性风格；
- 截图提供 AVIF、WebP 和必要的 PNG 回退；
- 为截图提供描述产品状态的 alt 文本；
- 装饰图形使用空 alt 或从可访问树隐藏；
- 不用 Emoji 代替图标。

## 交互与动画

### Hero 产品演示

截图上依次强调搜索框、结果引用和回答区域。用户可以点击热点切换步骤；自动演示只运行一次，并在用户交互、页面不可见或减少动画模式下停止。

### 工作流切换

四个步骤使用按钮实现，具备选中状态、键盘操作和关联面板。JavaScript 不可用时，所有步骤内容按静态顺序展示。

### Local-First 文件轨迹

使用内联 SVG 和 CSS 控制路径状态。`IntersectionObserver` 只添加增强状态，不负责首次显示内容。

### 下载反馈

使用 `navigator.userAgentData` 或保守的 user agent 判断突出推荐平台。检测结果仅是建议，用户始终能选择其他平台。下载开始后提供短暂状态反馈；链接仍保持原生跳转行为。

### 动画约束

- 仅使用原生 CSS、Web Animations API 和少量 JavaScript；
- 主要动画属性为 `transform`、`opacity` 和 SVG stroke；
- 不动画布局尺寸，不使用连续滚动监听；
- 首屏编排只运行一次，其他动画由用户点击或元素进入视口触发；
- `prefers-reduced-motion: reduce` 下停止自动播放和位移动画；
- 内容不能以动画执行成功作为可见前提。

## 技术实现路径

采用无前端框架的静态生成：

```text
landing/
├── PRODUCT.md
├── src/
│   ├── assets/
│   ├── content/
│   │   ├── en.json
│   │   └── zh-CN.json
│   ├── scripts/
│   ├── styles/
│   └── templates/
├── scripts/
├── docs/
├── dist/
└── package.json
```

### 构建

- 使用 Node.js 内置模块读取模板和结构化内容；
- 生成 `/en/` 与 `/zh-CN/` 静态页面；
- 根路径为 `x-default` 入口，提供英文默认内容和显式中英文链接；短脚本可以在首次访问时依据浏览器语言跳转，JavaScript 不可用时仍可继续浏览；
- 每个语言页面包含自引用 canonical、互相对应的 `hreflang` 和 `x-default`；
- 生产构建必须传入规范化的绝对 `SITE_URL`，用它生成 canonical、Open Graph URL、JSON-LD URL 和 sitemap；缺失或不是 `https://` URL 时构建失败；
- 部署平台保持开放，但必须支持静态目录和 `/en/`、`/zh-CN/` 路径；最终域名确定后只通过部署环境提供 `SITE_URL`，无需修改模板；
- `dist/` 是可直接部署的静态产物；
- 不引入 Vue、React、Tailwind、运行时模板或客户端国际化库。

### 内容与配置

- 中英文内容结构保持一致，但文案独立撰写；
- 双语 key 在构建时校验；
- 下载版本、架构、URL、最低系统版本和可用状态集中在 `src/content/releases.json`；
- GitHub URL 和 Release URL 来自真实仓库配置；
- 不在 HTML 中散落可变版本信息。

### 渐进增强

基础 HTML 提供全部内容、语言入口、导航和直接下载链接。JavaScript 只增强：

- 语言偏好记忆；
- 导航菜单；
- 产品演示；
- 工作流切换；
- 动画触发；
- 推荐下载识别与反馈。

## SEO 与分享

每种语言需要独立：

- `<title>` 与 meta description；
- canonical 和 `hreflang`；
- Open Graph 与 Twitter Card；
- 合适的 `lang` 属性；
- Product / SoftwareApplication JSON-LD。

项目同时生成：

- `robots.txt`;
- 使用 `SITE_URL` 生成的绝对 `sitemap.xml`;
- favicon 与 web app icons；
- 分享卡片图片；
- 语义清晰且稳定的锚点 URL。

结构化数据只能声明真实可验证的信息，不填写虚构评分或价格。

## 无障碍

最低目标为 WCAG 2.2 AA：

- 文字对比度至少 4.5:1；
- 大文字与非文本控件至少 3:1；
- 触控目标至少 44×44px；
- 提供跳过导航链接；
- 标题层级连续；
- 所有交互可用键盘完成；
- 焦点清晰可见，菜单关闭后恢复焦点；
- 语言切换使用可理解的文本标签；
- 产品热点不能成为获取信息的唯一方式；
- 页面缩放至 200% 后仍可使用；
- 支持减少动画和高对比偏好。

## 性能预算

- LCP ≤ 2.5s；
- CLS ≤ 0.1；
- INP ≤ 200ms；
- 首屏关键资源约 500KB 以内；
- 自有 JavaScript gzip 后尽量 ≤ 20KB；
- 非首屏截图懒加载；
- 图片显式声明宽高并按显示尺寸输出；
- 字体优先系统栈；自托管字体必须裁剪字重并设置合理 fallback；
- 不加载大型运行时、动画库和第三方追踪脚本。

Lighthouse Performance、Accessibility、Best Practices 和 SEO 的目标均为 95 以上，但以真实设备体验和 Core Web Vitals 为最终判断。

## 错误与降级

- 操作系统识别失败：展示全部下载项；
- 某平台暂无构建：显示明确不可用状态并链接 Release，不提供失效下载；
- `SITE_URL` 缺失或无效：生产构建失败，不生成带错误 canonical 的页面；
- Release 同步失败或三项资产不完整：保留上一次已审查的配置供本地预览，但生产构建失败；
- JavaScript 失败：保留完整内容、语言链接、FAQ 和下载链接；
- 图片加载失败：布局不坍塌，alt 文本仍解释内容；
- 外部链接失效：构建检查失败，阻止发布；
- 自动演示异常：回退到静态截图；
- 语言偏好不可写入：仅影响记忆，不影响当前页面。

## 验证

### 自动验证

- 构建可重复执行；
- 中英文 key 和必填 SEO 字段一致；
- HTML 语义和结构有效；
- 内部链接、资源路径和外部关键链接有效；
- 不存在缺失 alt、重复 id 和空 CTA；
- CSS、JavaScript 与首屏资源满足体积预算；
- `robots.txt`、`sitemap.xml` 和结构化数据可解析。

### 浏览器验证

至少验证：

- 375px、768px、1024px、1440px；
- Chromium、WebKit 和 Firefox；
- 中文、英文和浏览器语言首次选择；
- 键盘导航与焦点顺序；
- 减少动画模式；
- Hero 演示、工作流切换和移动菜单；
- macOS、Windows 和未知系统的下载推荐；
- 无 JavaScript状态；
- 慢速网络和图片加载失败状态；
- Lighthouse 与关键 Core Web Vitals。

## 风险

### 真实素材不足

产品截图和功能陈述必须与当前版本一致。实现前应从可运行产品中采集截图，并逐项核对公开能力。没有证据的功能不进入页面。

### 下载链接易过期

直接绑定具体资产 URL 会随版本变化。通过集中配置和 GitHub Release 回退降低维护成本，并在构建阶段检查链接。

### 双语内容漂移

结构化 key 校验只能保证字段存在，不能保证语义一致。发布前需要人工进行中英文内容审查。

### 轻交互逐渐膨胀

所有新动画必须回答“它解释了什么或改善了什么”。无法回答的动画不加入；JavaScript 体积预算作为硬边界。

### 官网超前承诺

Local LLM、文件类型和平台支持仍会演进。页面只展示已验证能力，版本相关内容集中配置，避免文案长期失真。

## 后续演进

只有在真实使用数据支持后再扩展：

1. 为高频搜索问题增加独立 use case 页面；
2. 增加版本更新日志或轻量文档入口；
3. 接入尊重隐私的匿名转化分析；
4. 增加真实用户案例；
5. 根据下载平台占比优化默认 CTA；
6. 当维护压力出现时，再考虑轻量内容系统。

首版不为这些未来方向预设 CMS、组件平台或复杂路由。
