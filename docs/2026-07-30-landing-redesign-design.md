# NoNote Landing Redesign

> Date: 2026-07-30
> Status: Approved direction, review fixes applied
> Scope: `landing` 独立仓库

## 用户目标

让第一次接触 NoNote 的个人知识工作者、开发者、研究者和重度文件用户，在十秒内理解：

1. NoNote 不是要求用户重建内容体系的另一款笔记软件；
2. 它让已经存在于电脑中的文件重新变得可搜索、可理解、可对话、可继续创作；
3. 当前产品已经真实可用，文件与控制权仍属于用户；
4. 访客可以直接下载适合 macOS 或 Windows 的版本，或前往 GitHub 验证项目。

首页的核心承诺是：

> 你的文件，不该只是被保存。

AI 能力是兑现承诺的方式，Local-First 是建立信任的理由，不把二者反过来当作空泛卖点。

## 核心 tradeoff

页面需要比旧版更有品牌记忆与体验高级感，但真实产品证据必须始终高于视觉炫技。

- 选择中等偏高的动态叙事，换取更强的体验和产品理解；
- 不使用 3D 场景、漂浮光球、装饰性粒子或无意义的连续运动；
- 动画必须解释文件如何进入、被理解并形成新产出；
- 产品截图只能来自当前 MVP 的真实运行界面；
- 演示 Workspace 和演示内容可以专门准备，但不得重画、生成或伪造不存在的产品 UI；
- 保持现有零运行时依赖的静态站结构，除非滚动编排验证后确实需要一个小型动画依赖。

## 设计方向

采用“价值路径”作为页面骨架：先呈现用户已有文件被闲置的问题，再展示 NoNote 如何完成“已有文件 → 理解与检索 → 新产出”的闭环。

视觉语言为 **Quiet Product Confidence with Directed Motion**：

- 白色和低色度绿灰承担清晰的产品展示；
- 深绿色承担品牌观点与 Local-First 信任叙事；
- 暖琥珀只用于文件流转、引用与产出等关键状态；
- 使用大幅真实产品界面、编辑式文字节奏与连续场景，避免 SaaS 模板式卡片墙；
- 字体继续使用跨平台原生 UI 字体栈，保证中英文覆盖、速度和与桌面产品的一致性；
- 页面不模仿 Notion、Linear 或 AI 紫色渐变风格。

## 页面叙事

### 1. Header

导航只保留有助于理解和转化的入口：工作方式、Local-First、下载、GitHub、语言切换。首屏内保持轻量，滚动后获得更明确的背景和边界。900px 以下收进可键盘操作的菜单，但下载保持独立可见；无 JavaScript 时直接显示可换行的普通链接，不隐藏导航。

### 2. Hero

标题使用“你的文件，不该只是被保存”，补充 NoNote 是面向已有本地资料的 Local-First AI 工作空间。

主要操作为“查看适合当前平台的下载”，点击后滚动到下载区，不自动开始下载；次要操作为 GitHub。首屏视觉使用当前 MVP 的真实四栏完整界面，清晰展示：

- 全局侧栏；
- Workspace 与文件树；
- 阅读或编辑区域；
- Assistant。

产品窗口不是装饰背景，而是首屏最重要的可信证据。

### 3. Problem

解释用户真正的问题不是缺少保存工具，而是文件在保存后逐渐失去上下文：

- 知道内容存在，却难以再次找到；
- 资料分散在文件夹、PDF、DOCX、Markdown 和笔记中；
- 阅读、问答和新产出之间没有连续路径。

该段避免恐吓式文案或夸张统计，用具体日常场景建立共鸣。

### 4. Workflow

用连续场景说明完整闭环：

1. 导入或继续使用已有文件结构；
2. NoNote 理解、索引并统一检索；
3. 在真实资料范围内与 Assistant 对话并查看引用；
4. 将结果保存为新笔记，回到本地知识体系。

桌面端通过同一真实产品窗口的焦点切换讲述过程；移动端改为顺序堆叠，避免横向缩小到不可读。

### 5. Why NoNote

深绿色品牌转折段回答“为什么做这个产品”：

> 我们已经保存了很多。真正缺少的是理解。

NoNote 不要求用户迁移到封闭内容系统或重新培养一套整理习惯，而是从用户已经拥有的文件开始。该段以品牌观点为主，不重复功能列表。

### 6. Local-First

通过可验证的边界建立信任：

- 文件保留在用户选择的数据位置；
- 本地模型和远程 Provider 由用户配置；
- 数据路径、任务状态与产品实现可检查；
- GitHub 和 Release 是进一步验证入口。

这里不使用绝对化隐私承诺，不把“Local-First”误写成所有模型请求必然离线。

### 7. Real Product Evidence

围绕当前 MVP 的真实能力展示局部产品图：

- 阅读与 Focus Reader；
- Workspace 搜索与文件结构；
- Assistant 引用和完整回答；
- Save as Note 或任务中心。

优先复用同一次真实运行会话的完整截图和裁切，维持内容、语言、窗口和状态连续性。

### 8. Download

根据当前平台突出推荐安装包，但始终展示本版本支持的安装器资产和 GitHub。校验和、源码归档及其他 Release 附件不进入主要下载选择。平台识别只改变强调，不隐藏选择、不自动下载：

- macOS Apple Silicon：突出 arm64 DMG；
- macOS Intel：突出 x64 DMG；
- Windows x64：突出 NSIS 安装包；
- Linux、未知系统或无法可靠区分 Mac 架构：不推荐单一资产，解释当前支持范围并展示所有可用下载；
- JavaScript 禁用：不做平台推荐，所有下载链接仍可见；
- Release 数据缺失、过期或某个资产不可用：对应按钮不得指向猜测 URL，显示明确状态并提供 GitHub Releases 入口。

首屏主操作只定位到下载区，所有实际下载都必须由用户再次明确点击。下载区复用首屏“已有文件重新有用”的视觉线索完成叙事闭环。

### 9. Footer

只保留项目、GitHub、Release、许可证、语言和必要版权信息，不扩展博客、社区、客户 Logo 或不存在的社会证明。

## 产品素材规则

旧 `product-preview.jpg` 是概念预览，不再作为生产官网的产品证明。

新版素材必须从当前 NoNote MVP 实际运行产生。允许创建不含个人信息的演示 Workspace，例如研究资料、产品文档和会议记录；界面布局、控件、状态和操作结果不得通过图像生成或重绘改变。

至少采集：

1. 完整四栏工作台；
2. 带正文的阅读或 Focus Reader；
3. 带真实引用的 Assistant 回答；
4. Save as Note 或任务中心场景。

每张生产图片及其裁切都必须映射到素材清单中的一条记录，包含：

- 生产文件名与原始源文件名；
- 应用 commit 或 release tag；
- 操作系统；
- 界面语言；
- 场景与操作步骤；
- 裁切、压缩、二维变换或隐私遮盖说明；
- 隐私复核结果。

网页允许对真实截图做裁切、透视程度很低的二维变换、遮罩和分层动画，但不得生成截图中不存在的 UI。输出优先提供 AVIF/WebP 和 PNG/JPEG 回退，并声明固有尺寸避免布局偏移。

中文页使用中文 UI 截图，英文页使用英文 UI 截图；连续性以“同一语言、同一场景、同一次运行会话”为单位，不要求中英文截图处于同一会话。完整四栏图只在足够宽的视口展示。移动端使用来自同一真实源图的阅读区、文件树和 Assistant 定向裁切，配本地化说明；允许提供可键盘关闭并恢复焦点的原生 `<dialog>` 放大查看，但不重排或拼造原图中的 UI。

截图内文字不承担唯一信息。信息性截图提供本地化 `alt` 和可见说明；只用于氛围或重复同一事实的裁切使用空 `alt`。工作流的每个状态都有等价正文。

`product-preview.jpg` 及其任何派生概念图不得再被生产 HTML、CSS、JavaScript、结构化数据、Open Graph 或 Twitter 元数据引用。素材清单和自动化测试需要验证这一点。

## 动效设计

动效强度为中等偏高，但每段都服务于内容。

### 首屏编排

标题与说明先建立理解，真实产品窗口随后从下方展开。窗口内部按照文件树、阅读区、Assistant 的顺序轻微强调，表达“资料 → 理解 → 对话”，随后停止自动播放。

### 工作流滚动叙事

桌面端允许产品窗口在有限滚动距离内保持视觉中心，文案和截图焦点依次切换。状态变化使用遮罩、裁切、轻微景深和颜色强调，不对截图做夸张三维旋转。

### 文件流转

二维路径、光标位置、引用连线和状态确认用于解释文件如何形成新产出。没有业务含义的粒子、光斑和持续漂浮一律不加入。

### 品牌转场

从明亮产品区进入 Why NoNote / Local-First 深绿色区域时，使用颜色铺展、遮罩和内容节奏变化建立沉浸感；转场结束后保持稳定阅读。

### 微交互

导航、语言选择、平台下载、能力切换和产品图查看提供 150–300ms 的 hover、focus、press 与状态反馈。所有点击目标至少 44×44px。

### 性能与可访问性

- 默认使用 CSS 动画、`IntersectionObserver` 和 `requestAnimationFrame`；
- 只有原生实现无法稳定表达滚动编排时才评估小型动画依赖；
- 优先只动画 `transform`、`opacity`、`clip-path` 和合成友好的滤镜，不在逐帧循环中读写布局；
- sticky 叙事最多占 160vh，桌面同时活动的截图层不超过 3 层，完成后停止 observer 和 RAF；
- 不让内容初始依赖透明状态，脚本失败仍可阅读；
- 页面隐藏时暂停自动演示；
- `prefers-reduced-motion` 下移除空间位移、滚动绑定和自动演示，保留即时状态切换；
- 移动端缩短编排并取消 sticky 长段，优先保证内容与产品图可读；
- 避免动画影响 LCP、CLS 和交互响应。
- 自动演示单次不超过 6 秒；单帧脚本工作目标低于 8ms，不出现超过 50ms 的动画长任务；
- 在一台代表性低功耗移动设备或浏览器节流环境中验证滚动，不允许出现可重复的掉帧停顿。

## 双语内容

继续生成英文默认页和中文页。两种语言保持相同事实与信息架构，但分别自然创作，不做逐字翻译。

中文主标题：

> 你的文件，不该只是被保存。

英文主标题：

> Your files were meant to become more.

品牌记忆句保留：

> NoNote — Not Only Notes. Everything you keep, finally useful.

## MVP 范围

本轮包含：

- 重写中英文页面内容；
- 重构首页信息架构与视觉系统；
- 使用真实 MVP 产品截图替换概念图；
- 实现首屏、工作流、品牌转场和微交互动效；
- 响应式、键盘访问、减少动态效果与无 JavaScript 降级；
- 更新素材来源记录、构建测试和页面测试；
- 在常见桌面与移动视口中进行真实浏览器截图检查。

本轮不包含：

- 3D、WebGL 或视频背景；
- CMS、博客、账户、邮件收集和分析后台；
- 虚构客户评价、下载量、媒体 Logo 或合作伙伴；
- 为官网重画一套与产品不同的演示 UI；
- 改动 NoNote 桌面应用功能。

## 技术实现路径

沿用当前静态生成器：

- `src/content/*.json` 管理双语事实与文案；
- `scripts/build.mjs` 生成静态 HTML、SEO 元数据、sitemap 与静态资产；
- `src/assets/styles.css` 承担 token、布局、组件、响应式和 reduced-motion；
- `src/assets/main.js` 承担渐进增强、平台识别、滚动场景与键盘交互；
- `<picture>`、显式尺寸和现代图片格式承担产品图交付；
- 核心内容、语言入口和下载链接在 JavaScript 禁用时仍然可用。

若单文件已经阻碍理解，可按页面结构拆分构建期 partial 和浏览器端小模块，但不引入框架或提前建立组件系统。

交互状态约束：

- 菜单、工作流切换和截图放大均支持键盘、Escape 和关闭后的焦点恢复；
- 语言切换保留当前 section hash；目标语言缺少对应锚点时回到页面顶部；
- 所有状态除颜色外同时使用文字、形状或位置表达；
- Release 数据构建失败时保留上一次经过验证的数据并标注版本；不存在可验证数据时只链接 GitHub Releases，不输出伪造资产链接。

## 验收

### 用户价值

- 对至少 3 名未参与设计的人进行 10 秒首屏测试；询问“这是什么、解决什么、内容在哪里”，至少 2 人的回答同时包含“已有/本地文件”“搜索、理解或对话”“文件仍由用户控制”中的前两项，且无人误认为纯在线笔记服务；
- 能理解从文件到搜索、对话和新笔记的闭环；
- 能找到当前系统下载入口和 GitHub；
- 能从真实产品图判断当前产品形态。

### 真实性

- 页面不再使用概念 UI 作为产品证明；
- 所有产品图可追溯到当前 MVP 的实际运行；
- 不含个人路径、密钥或真实私人资料；
- Local-First 文案与实际远程/本地 Provider 边界一致。
- 每项 Local-First 声明都链接到对应产品界面、公开源代码或 Release 说明；明确写出选择远程 Provider 时，用户选定的相关内容可能发送给该 Provider。

### 体验

- 动效与页面叙事一致，没有无意义的持续动画；
- 375、768、1024、1440px 无横向溢出；
- 375px 使用定向真实裁切和等价正文，不缩放完整四栏图来承担产品说明；
- 键盘、可见焦点、44px 目标和 WCAG 2.2 AA 对比度通过；
- reduced-motion 和无 JavaScript 场景可完整阅读与下载。
- 200% 和 400% 缩放下正文与控件可重排且页面本身不产生横向滚动；产品截图可以等比缩放，放大图只能进入带明确标签、键盘可操作的局部平移/缩放区域；VoiceOver 或 NVDA 抽查 landmark、链接名称、菜单、切换和 dialog；关键状态不依赖颜色识别。

### 工程

- `npm run check` 通过；
- 静态构建可重复；
- 中英文内容结构一致；
- 图片声明尺寸且没有明显 CLS；
- 浏览器控制台无错误；
- 动画不造成长任务或明显滚动卡顿。
- Lighthouse 移动模拟目标：Performance ≥ 90、Accessibility ≥ 95、Best Practices ≥ 95、SEO ≥ 95；CLS ≤ 0.1、LCP ≤ 2.5s、TBT ≤ 200ms；
- 首屏移动资源预算不超过 700KB，桌面不超过 1.2MB；首屏外产品图懒加载，单张现代格式产品图不超过 450KB；
- Chrome、Safari、Edge 当前稳定版和 Firefox 当前稳定版完成核心路径抽查；
- 375、768、1024、1440px 形成基准截图并按导航、文案、图片裁切、溢出、焦点和 reduced-motion 清单人工复核。

## 素材新鲜度

每张截图记录其应用 commit 或 release tag。若当前待发布应用在首屏涉及的导航、四栏布局、阅读器、Assistant 或下载状态中任一项发生可见变化，对应截图即视为过期，发布前必须重新采集；仅内部实现变化不触发重采集。构建测试负责检查记录完整性与旧概念图引用；每次官网发布由维护者对照记录的 commit/tag 与当前 Release 完成人工视觉复核。

## 风险

1. **真实产品图准备成本**：需要运行当前 MVP、准备安全演示数据并形成连续状态；不能用假 UI 快速替代。
2. **滚动叙事过重**：sticky 和截图切换可能损害移动端与低性能设备；必须采用桌面增强、移动收敛策略。
3. **产品迭代导致素材过期**：截图需记录版本，并尽量用完整源图派生裁切，降低更新成本。
4. **隐私表述过度**：远程 Provider 场景不能被描述为完全离线；文案要区分文件本地保存与模型请求路径。
5. **静态站代码膨胀**：优先维持简单数据流，只有单文件明显失控时才做小范围拆分。

## 后续演进

上线后先观察访客是否能理解核心价值以及下载路径是否顺畅，再决定后续方向：

- 若产品理解仍弱，优先优化工作流场景与文案，而不是增加功能列表；
- 若信任仍弱，增加可验证架构说明或公开隐私边界页面；
- 若截图频繁过期，建立可重复的演示 Workspace 和素材采集清单；
- 若动效对转化有明确收益，再评估更精细的截图序列或轻量视频；
- 只有出现持续内容运营需求时才考虑 CMS 或案例系统。
